HOW
dsh 0.2.1-rc.2 (DeepSeek's own agent, headless profile) sends the tier from its profile overlay
(agent-default-model.reasoningEffort) to DeepSeek's Anthropic-compatible API as output_config.effort - the same
field and endpoint as the Claude Code rows (see 20261017-dsv41flash1017-deepseek-effort.txt for the endpoint's
own validation: low, high and max accepted, an invented tier refused with 422). A pass-through logger sat between
dsh and the API for every leg and recorded, per request, the model, output_config.effort and DeepSeek's usage.
Main loop, subagents and side calls are all on the wire, so the counts below cover every agent dsh ran.

READING
Every main-loop and subagent request carried the row's tier. Two kinds of request did not:
  - one per leg with no effort field: a single-message call with thinking disabled, no tools and max_tokens 4096
    (a side call outside the reasoning loop - consistent with dsh naming the session);
  - one request in all the max runs went out at high: max r8, repo 1, a 527-message call with max_tokens 65536,
    consistent with dsh condensing a long context at a tier of its own. It is 1 of 7,123 max requests.
So the tier describes the agents dsh ran for the task; dsh's own housekeeping calls are not governed by it.
