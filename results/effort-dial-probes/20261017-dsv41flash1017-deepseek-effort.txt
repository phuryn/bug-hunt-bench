WHAT CHANGED SINCE 2026-09-10
DeepSeek released DeepSeek-V4.1-Flash-1017 on 2026-10-17 under the SAME model id. Its pricing page, read the
same morning: "deepseek-flash" -> model version DeepSeek-V4.1-Flash-1017; the legacy ids deepseek-v4-flash and
deepseek-v4-flash-vision-exp "are still accepted, but the corresponding models have been retired" and route to
1017. So the 2026-09-10 rows and this one share an id and differ in checkpoint.

2. DOES THE ENDPOINT VALIDATE THE TIER?  (POST /anthropic/v1/messages, model deepseek-flash, max_tokens 32)
    output_config.effort = "max"        -> HTTP 200, served model = deepseek-flash
    output_config.effort = "high"       -> HTTP 200
    output_config.effort = "low"        -> HTTP 200
    output_config.effort = "xhigh"      -> HTTP 200  (a compat alias; DeepSeek maps it to high)
    output_config.effort = "bogus_zzz"  -> HTTP 422
        "Failed to deserialize the JSON body into the target type: output_config.effort: unknown variant
         `bogus_zzz`, expected one of `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `ultra`, `max`"

The rejection moved from HTTP 400 (2026-09-10) to HTTP 422 with the same deserializer message and the same
enum. It is still an announced rejection that names the accept-list, so a silent clamp is not possible on this
path. The launch gate run before the legs accepts 400 or 422 when the body says "unknown variant".
