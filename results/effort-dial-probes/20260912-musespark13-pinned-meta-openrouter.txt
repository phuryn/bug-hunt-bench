CONCLUSION - WHERE THE FIELD DIES, AND WHY THE PIN COULD NOT HAVE HELPED

  1. OpenRouter lists ONE endpoint for this model: Meta. Confirmed by the endpoints API and by the
     per-request lookup above. There was never a second provider to be routed onto, so the pin is a
     no-op and provider variance cannot explain the null.
  2. An invented effort string returns HTTP 200 through OpenRouter on BOTH documented spellings,
     pinned and unpinned.
  3. OpenRouter is not simply permissive: the same request shape with a bad MODEL id returns a clean
     400. It validates what it handles.
  4. Meta's own endpoint 400-REJECTS invalid effort strings - verified on Muse Spark 1.2 in Aug 2026,
     where `max`, `ultra`, `none` and `minimal` were all rejected and low/high separated cleanly
     (1,055 / 1,738 / 1,999 thinking tokens).

  (2) + (4), given (1), can only be reconciled one way: the effort field never reaches Meta. If it
  did, Meta would reject `bogus_zzz` the way it does on its own endpoint. OpenRouter accepts the
  parameter, does not forward it, and Meta serves its default every time.

  That is a stronger result than the magnitude null. Magnitude can only say the dial did not move;
  this says which hop broke it. The dial is not absent from the model - it is absent from the path.

PRACTICAL CONSEQUENCE. Any Muse Spark 1.3 arm routed through OpenRouter runs at DEFAULT thinking
whatever the harness asks for, and must carry effort_status `inert_default` with effort `default`.
The honest-looking alternative - recording the tier that was requested - would put a number in the
effort column that no part of the system ever applied.

The contrast is the point. Glimmer is open-weights and four independent hosts serve it; every Spark
model is served by Meta alone. Spark is closed, so there is no third-party inference provider to try -
not a gap in our account coverage, an absence in the market. None of the other keys on this machine
(DashScope, DeepSeek, Moonshot, Z.ai, xAI, Gemini, OpenAI, Anthropic) serve Meta frontier models.

Two candidate paths remained. Both tested, both closed:

  1. META DIRECT - still HTTP 402, "Billing verification failed. Please check your payment method."
     Byte-identical to the failure recorded on 2026-08-06, which is why the 1.2 arm was routed through
     OpenRouter in the first place. This is the ONLY path where the dial is known to work (1.2:
     low 1,055 / high 1,738 / xhigh 1,999, invalid tiers 400-rejected), and it has been unavailable
     for five weeks.

  2. THE CONTRIBUTOR TIER on OpenRouter - a genuinely different serving path, ~12x cheaper
     ($0.10/$0.20 per MTok against $1.25/$4.25). Same result: `bogus_zzz` returns HTTP 200 on both
     spellings. The effort field is dropped there too.

So the answer is that there is nothing left to test. Every reachable path to this model runs at
default thinking, and the one path that honours the dial is behind a payment failure.

A WARNING ABOUT THE CHEAP TIER, because a 12x discount on a $10 bench run is a tempting thing to
reach for. Meta's contributor tier buys that discount with permission to train on prompts AND
completions; the standard tier is contractually excluded from training (verified 2026-08-06 from live
rate-limit headers when the 1.2 arm was priced). Fine for a throwaway maths word problem like the one
in these probes. Disqualifying for a bench arm, because repo 2 is client code that this board is
required to keep unpublished - a discount does not buy the right to hand it to a training set.
